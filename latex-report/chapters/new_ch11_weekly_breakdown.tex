\chapter{Weekly Implementation Breakdown}
\label{chap:weekly_breakdown}

The internship ran from Mar~15 to Aug~31, 2026 --- 24 working weeks at
part-time intensity for Weeks~1--4 (Mar~15--Apr~12, $\sim$10--20~h/week)
transitioning to full-time from Week~5 onwards ($\sim$40~h/week). The
following narrative documents what I delivered, encountered, and learned
each week, aligned to Monday--Friday calendar weeks.

% ────────────────────────────────────────────────────────────
\section{Weeks 1--4: Onboarding (Mar~16 -- Apr~10)}
\label{sec:wb_weeks1_4}
% ────────────────────────────────────────────────────────────

\subsection*{Week 1 \hfill Mar~16--20, 2026}

First week of engagement, part-time ($\sim$10~h). Filed Day~1 access requests
for AWS console, JIRA, Confluence, and CodeCommit. Attended daily standups
as the primary orientation mechanism. Reviewed Confluence architecture
documentation for the six IA platforms (\texttt{automationhub},
\texttt{bpm}, \texttt{citcoworks}, \texttt{ia-bpo}, \texttt{meridian},
\texttt{rpacfs1}) and mapped Lambda, ECS, and EC2 workloads across them.
Security onboarding session with Kishor covered access boundaries,
credential management policy, and JIRA workflow.

\subsection*{Week 2 \hfill Mar~23--27, 2026}

Access requests cleared. Began first concrete deliverable: RPACFS1
CloudWatch pipeline health dashboard (IISS-435) targeting the
\texttt{rpacfs1-cais-pricing-extract-genai-infrastructure} repository.
Dashboard included Lambda function monitoring and Logs Insights error
widgets. Confluence documentation for Amazon tools completed.

\subsection*{Week 3 \hfill Mar~30 -- Apr~3, 2026}

IISS-435 completed. Pivoted to IISS-455: Lambda monitoring CloudWatch
dashboard for \texttt{rpacfs1} and \texttt{ia-bpo}, enumerating 51
Lambda functions via \texttt{SEARCH()} expressions. Initial inventory
work surfaced the first instance of the SEARCH() visibility gap: functions
not invoked over the preceding weekend returned zero results on Monday morning.

\subsection*{Week 4 \hfill Apr~6--10, 2026}

IISS-455 dashboard deployed; IISS-461 Confluence Lambda inventory page
(51 functions with owner/trigger mapping) published. IISS-469 started:
extending the dashboard to \texttt{cfsbpm}, \texttt{citcoworks}, and
\texttt{meridian} platforms. Kishor reviewed an early prototype and
scoped the extension requirements for IISS-487: three additional platform
tag dimensions, multi-tag filter logic, and the Confluence inventory page.
The IAM boundary constraint for \texttt{logs:PutSubscriptionFilter} was
confirmed: 106 subscription filters would be needed but are blocked by
the scoped permission set.

% ────────────────────────────────────────────────────────────
\section{Week 5: Training Week \& Meridian Incident (Apr~13--17)}
\label{sec:wb_week5}
% ────────────────────────────────────────────────────────────

\subsection*{Week 5 \hfill Apr~13--17, 2026}

Full-time engagement began. The week was designated as a formal
knowledge-transfer week with four structured sessions:

\begin{itemize}
    \item \textbf{RPA Support Model (Horace)} --- Blue Prism and UiPath
          operational model, pool/queue architecture, VPL queue monitoring
          (5~PM~EST daily), Corporate Actions three-track workflow
          (Mandatory, Voluntary, Ops Transfer), and the Follow-the-Sun
          escalation ladder.

    \item \textbf{CitcoWorks and Event Store (Bhanu Teja Murari)} ---
          CitcoWorks Knowledge Graph (L1--L5 hierarchy backed by Neptune),
          Event Routing Service and Action Processor deployment model, and
          the Event Store structured logging library (mandatory fields:
          \texttt{subject}, \texttt{process\_identifier}, \texttt{run\_id}).

    \item \textbf{Meridian Platform (Meridian team)} --- three-stage Kafka
          event pipeline (ERS → MSK topics → OpenSearch Consumer → AXI),
          six ECS clusters hosting Meridian services, and consumer lag as
          the primary health indicator.

    \item \textbf{\AE xeo Treasury Platform} --- cloud-based wire approval
          and fund movement via COMAPI and the \AE xeo Reporter Server REST
          API; key workloads used by MESO and E-Binder reconciliation.
\end{itemize}

On Apr~17 (Friday), the Meridian Incident occurred: a surge of automated
events from Citco Recs congested the OpenSearch consumption layer, causing
$\sim$9~million Kafka messages to queue. Detection latency was 3.5~hours;
full restoration took 7.5~hours. No MSK consumer lag alarm existed. This
incident directly motivated IISS-487 and established \texttt{EstimatedMaxTimeLag}
as the primary MSK SLI. IISS-469 was completed this week.

\section{Week 9: Infrastructure Deployment Day (May~11--15)}
\label{sec:wb_week9}
% ────────────────────────────────────────────────────────────

\subsection*{Week 9 \hfill May~11--15, 2026}

The most infrastructure-dense week of the internship. On \textbf{May~11},
four CloudFormation stacks deployed in sequence:
\texttt{ia-sre-lambda-alarms}, \texttt{ia-sre-ecs-alarms},
\texttt{ia-sre-sqs-alarms}, and \texttt{ia-sre-msk-alarms}.
Grafana AMG workspace provisioned with 16-role IAM agent permission model.
Container Insights enabled on five of the six Meridian clusters.
The MSK \texttt{EstimatedMaxTimeLag} alarm armed itself against live
production traffic --- the first alarm that would have detected the
Meridian Incident.

On \textbf{May~13}, the AMG workspace was upgraded (unplanned) from
Grafana~10.4 to~12.4. Breaking changes in the Metric Insights SQL editor
and template variable interpolation syntax consumed approximately one working
day migrating all panels to the stable 12.4 query model. This experience
motivated NFR6: use only standard CloudWatch plugin queries.

Dashboard Rows~1--3 (Health Overview, Performance Overview, SQS) and early
Lambda rows built by May~15.

\section{Weeks 10--11: Dashboard Build Intensive (May~18--29)}
\label{sec:wb_weeks10_11}
% ────────────────────────────────────────────────────────────

\subsection*{Week 10 \hfill May~18--22, 2026}

Lambda, ECS, EC2, and MSK/Kafka rows built. Metric Insights SQL percentile
limitation confirmed: \texttt{GROUP BY} mode supports only AVG/SUM/MIN/MAX;
p50/p99 unavailable. Implemented wildcard dimension workaround
(\texttt{FunctionName:~["*"]}) for Lambda duration percentile panels
--- accepting the idle-function visibility tradeoff.

Secrets Manager 64~KB limit hit: the CloudFormation provisioner payload
grew to \textbf{14,720~lines} at version~v438, triggering
\texttt{SecretSizeExceeded}. Migrated all alarm templates to S3 object
storage; provisioner updated to fetch via \texttt{s3:GetObject} at deploy
time.

\subsection*{Week 11 \hfill May~25--29, 2026}

DocumentDB, Neptune, Redis/Valkey, OpenSearch, and RDS rows completed.
OpenSearch JVM heap pressure alarm wired --- OpenSearch was the bottleneck
in the Meridian Incident. SNS Re-Notifier Lambda deployed for ongoing alarm
state reminders. Eight composite alarms configured to aggregate per-service
states into per-platform OK/ALARM indicators (Row~12). Phase~2 total:
\textbf{157 hours}. Detection latency for a Meridian Kafka event now
projected at $<$30~seconds.

\section{Week 13: CAIS Hotfix \& SQS Feature (Jun~8--12)}
\label{sec:wb_week13}
% ────────────────────────────────────────────────────────────

\subsection*{Week 13 \hfill Jun~8--12, 2026}

Most incident-dense week. IISS-706: CAIS Deadline process failed with
\texttt{SMBAuthenticationError: SpnegoError} on UCM upload. 7-hour
investigation identified \texttt{constants.py} module-import-time credential
caching as the root cause --- credentials fetched once at container start,
a Secrets Manager rotation leaving empty values caused silent failures.
Hotfix added fail-fast validation in \texttt{constants.py} and
\texttt{pysmb\_helper.py}. CAIS filing completed before regulatory deadline.

In parallel: IISS-507 inventory API scaffolded via Kiro spec-driven
workflow (2.5~hours). IISS-482 SQS monitoring feature completed with
\textbf{960 automated tests} covering registry dispatch, 3-tier fallback,
and dashboard builder integration.
