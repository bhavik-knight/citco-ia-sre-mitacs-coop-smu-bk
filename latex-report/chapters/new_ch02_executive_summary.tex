\chapter{Executive Summary}
\label{chap:executive_summary}

This report documents my Mitacs Business Strategy Internship (BSI)
at Citco Technology Management (CTM), Halifax, Nova Scotia, conducted between
\textbf{March~15 and August~31, 2026} under the project title
\textit{``Intelligent Automation and Reliability Engineering for Financial
Services''} (Mitacs reference IT49539).

Before I joined, the IA-IT-SRE team had no centralized observability platform
for the IA-IT-SRE Infrastructure --- a collection of six platforms
(\texttt{automationhub}, \texttt{bpm}, \texttt{citcoworks}, \texttt{ia-bpo},
\texttt{meridian}, \texttt{rpacfs1}) spanning Lambda functions, ECS clusters,
EC2 instances, MSK Kafka pipelines, and a range of database and messaging AWS
services. Two documented production failures --- a 29-day silent outage of the
CAIS-Pricing (Citco Alternative Investment Services) GenAI pipeline and a 7.5-hour Meridian event processing
delay --- both went undetected until business teams escalated them,
exposing the team's reliance on reactive, manual incident detection. The
research question framed for this engagement was: \textit{can AWS-native
services achieve Dynatrace-equivalent observability at a fraction of the cost?}

My approach was incremental across three phases. I first built CloudWatch
dashboards targeting Lambda functions --- the AWS service at the center of the
silent outage --- and documented each function's trigger type and runtime across
all six platforms. I then developed a
registry-based IA Infrastructure inventory API that queries the AWS
API dynamically and returns live, per-platform lists of all deployed AWS
services. Finally, I built a centralized Amazon
Managed Grafana (AMG) workspace as a proof-of-concept, covering all AWS
service categories used by the IA infrastructure across all six platforms via dynamic platform template
variables. The RPA production support rotations ran in parallel
throughout the co-op placement.

The key outcomes of this work are:
\begin{itemize}
    \item Kafka consumer lag detection reduced from a 3.5-hour business-team
          escalation window to \textbf{under 30 seconds} via a CloudWatch MSK
          \texttt{EstimatedMaxTimeLag} alarm, directly addressing the
          Meridian Incident failure mode
    \item Dynamic CloudWatch alarms deployed across all monitored AWS services
          on all six platforms, where none or limited existed before
    \item Grafana AMG workspace with \textbf{multiple rows} covering every AWS
          service category in the IA-IT-SRE Infrastructure
    \item AWS service inventory across all six platforms, with
          \textbf{99\% automated test coverage} on the inventory API
    \item AWS-native stack achieves \textbf{$\sim$60\% Dynatrace feature
          parity} at \$77/month (CloudWatch + Grafana AMG + X-Ray), rising
          to \textbf{$\sim$80\%} with Application Signals
\end{itemize}

The chapters that follow detail the tools and technologies used, the full
project context and JIRA scope, the SRE methodology and requirements, the
phased technical implementation, and the broader learning outcomes of the
engagement.
