**6. CloudFormation Deployment Failure — Template Size Limit Investigation**
A CloudFormation deployment failure was investigated and traced to the AWS inline template body limit of 51,200 bytes. The alarms.yaml template had grown to 55,766 bytes across the IISS-487 work stream through the addition of composite alarms, the Re-Notifier Lambda, SNS topics, IAM roles, and EventBridge rules. The investigation confirmed that the template content is valid and the failure is solely due to the size constraint, establishing S3-based template staging as the required resolution path.

**7. CloudFormation Deployment — upload_template_s3() Function Implementation**
An upload_template_s3() function was implemented in deploy_stacks.py to stage CloudFormation templates in S3 before deployment. The function handles uploading the template file to the designated S3 bucket and prefix, returning the S3 URL for use in subsequent CloudFormation API calls. AWS CloudFormation accepts templates up to 1MB when referenced via an S3 URL, providing sufficient headroom for continued template growth across future sprints.

**8. CloudFormation Deployment — S3 URL Integration for deploy_stack() & preview_stack()**
The deploy_stack() function was updated to use --s3-bucket and --s3-prefix flags so the AWS CLI handles S3 upload automatically during stack creation and update operations. The preview_stack() function was updated to use upload_template_s3() combined with --template-url for change set creation operations. Both functions now route all template submissions through S3, eliminating the inline body size constraint for all current and future template deployments.

**9. Deployment Pipeline — deploy.py Callers Updated with S3 Bucket Parameter**
All callers in deploy.py were updated to pass the S3 bucket parameter to the deployment functions, ensuring the S3-based template staging path is used consistently across all deployment entry points. This change completes the S3 migration by ensuring no code path remains that would attempt inline template submission for templates that have exceeded or may exceed the size limit.

**10. --dry-run Alias Bug — Investigation & Fix**

This caused dry-run invocations to execute validation logic instead of the intended dry-run behaviour, producing misleading output. The alias mapping was corrected so --dry-run operates independently, and the fix was verified against the expected dry-run execution path.
