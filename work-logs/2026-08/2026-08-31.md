### SD #15516869 — AROHI / ARSPC1 PreMESO Critical — Full RCA

**Incident summary:**

| Field | Detail |
|-------|--------|
| Client | AROHI |
| Fund | ARSPC1 |
| Process | RPA - Position Completeness |
| Value Date | 08/01/2026 - 08/28/2026 |
| Error | "Script Error" in Position Completeness email notification |
| Trigger Attempts | 2 (ALL run + POSITION-only run) |
| Business Impact | Critical - Client Deliverable Impacted |

**Root cause:** `Clear Broker` column in the Aexeo `PB_APL` (Active PnL) report for ARSPC1 contains numeric broker codes (e.g. `12345`) instead of alphabetic mnemonics used by all other funds (e.g. `"GSCO"`, `"MLCO"`). On load, `Clear Broker` retains `int64` dtype. It is then used as a join key in an outer merge against `ART Broker Codes` which is always `str`. Pandas cannot align incompatible types in a merge key — merge fails or produces entirely unmatched result. Downstream crash sets `status = 2` — surfaced as "Completeness Script Error". Both trigger attempts hit the same code path.

**Why only AROHI/ARSPC1:** Data-driven. ARSPC1's broker codes in Aexeo are CMS-style numeric identifiers. All other active funds use alphabetic codes so implicit string inference has always worked. No fund-specific code in the pipeline — purely a dtype difference in what Aexeo returns.

**Affected files:**

| File | Location | Issue |
|------|----------|-------|
| `data_loading.py` | `load_active_pnl()` | `converters` dict missing `Clear Broker` entry — numeric values load as `int64` from Excel |
| `data_processor.py` | `process_backup()` groupby | `Clear Broker` not cast to `str` before groupby — raises `TypeError` on mixed types |
| `data_processor.py` | `merge_data()` both outer merges | `Clear Broker` (`int64`) merged against `ART Broker Codes` (`str`) — type mismatch on join key |

**Proposed fix (3 targeted changes — string normalisation only, no logic changes):**

1. `data_loading.py` — `load_active_pnl()`: add `'Clear Broker': str` to `converters` dict
2. `data_processor.py` — `process_backup()`: add `backup_df['Clear Broker'] = backup_df['Clear Broker'].fillna('').astype(str)` before groupby
3. `data_processor.py` — `merge_data()`: add same cast before first outer merge

`ART Broker Codes` side (rec file) already protected by `converters={'ART Broker Codes': str}` — these changes bring backup side in line.

**Workaround:** None available while fix pending. Report must be generated manually for impacted dates once fix applied and process retriggered.

**Action:** Did full RCA, emailed Horace and team. Fix implemented in commits `8b250cc`/`cbb37e2`/`aca1425` (ia_meso_process, same day).
