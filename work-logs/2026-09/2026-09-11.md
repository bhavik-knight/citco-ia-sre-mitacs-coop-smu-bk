## Timecard

**ml-rpa-status-llm-agent — Usage Analytics Email Enhancement**

1. Weekly Usage Email Redesign — YTD/MTD Analytics Cards and Pivot Table
The weekly usage email was comprehensively redesigned to provide operational analytics context beyond the previous simple query count. New sections include YTD (year-to-date) and MTD (month-to-date) query count stat cards, a 7-day rolling summary table showing daily counts and trends, and a pivot table breaking down query volume by day of week. These additions enable the support team to identify usage patterns, peak periods, and growth trends at a glance.

2. Email Client Compatibility Fix — CSS Gap Property Replaced
The usage email HTML template was using CSS `flexbox gap` for spacing between stat cards. Outlook and Gmail do not support the `gap` property in table-based layouts, causing cards to render without spacing in the most common corporate email clients. The `gap` property was replaced with explicit `margin-right` values on individual elements, restoring correct layout across all tested email clients.

3. AKehm Recipient Addition — PROD Email Distribution Expansion
The PROD recipient list for the weekly usage email was updated to include the `AKehm` distribution address, expanding the operational visibility of usage metrics to additional stakeholders.

4. Logging Dependency Iteration — stdlib Logging Selected Over structlog
An attempt was made to use `structlog` for the usage Lambda function to maintain consistency with other Lambda functions in the stack. After encountering packaging and import complications, the decision was made to use Python's `stdlib logging` module instead, which has no external dependency requirements. The `log_config.py` module was added to the buildspec copy step to ensure it is available at runtime.

**ml-rpa-status-llm-agent — Agent Instruction Quality**

5. Concrete Table Example — Sonnet 5 Format Enforcement
Claude Sonnet 5 was inconsistently reverting to bullet-format responses for process status queries despite the global table-format instruction. A concrete 3-row table example was added to the instruction to provide a worked example that Sonnet 5 could use as a direct format reference. This pattern (global rule + worked example) proved more effective than rule statements alone for format enforcement.

**IISS-971 — MESO Scheduled Reports Infrastructure**

6. SR Queue and EventBridge Rules — Clean Re-Implementation
Following the Sep 9 revert, the Scheduled Reports SQS queue and 6 EventBridge rules were re-implemented from scratch with the correct IAM and KMS permissions model in place from the start. The new implementation resolved the permission gaps identified during the initial deployment attempt and was successfully deployed to DEV for integration testing.
