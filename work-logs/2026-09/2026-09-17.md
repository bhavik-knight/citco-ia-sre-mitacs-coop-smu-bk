## Timecard

**IISS-507 — Infrastructure Inventory API: SQS Queue Type Enrichment**

1. FIFO-DLQ Queue Type — Composite Classification for FIFO Dead Letter Queues
FIFO queues that also serve as Dead Letter Queues (DLQs) were not being classified correctly by the initial `queue_type` implementation. The detection logic was updated to check both the `FifoQueue` attribute and the presence of a `RedriveAllowPolicy` simultaneously, yielding a distinct `fifo-dlq` classification. This ensures operators can identify the full topology of FIFO queue chains, including their error capture queues.

**IISS-1050 — SMB Retry Decorator: TRANSFER_FAILED Prevention (SD #15645338)**

2. SMB Transfer Retry Decorator — Transient Failure Recovery
The `transfer_to_share_drive()` function was identified as a single point of failure for transient SMB connectivity issues (network blips, share drive restarts under load). A tenacity `@retry` decorator was added with 3 maximum attempts, exponential backoff starting at 2 seconds, and a maximum wait of 30 seconds. This change transforms what were previously permanent job failures into recoverable events for the majority of transient network conditions.

3. IISS-1050 PR #12 Merge — Retry Feature Integrated to Main
Pull request #12 was merged following review, integrating the retry decorator into the main branch. The feature was deployed to DEV for validation before the subsequent PR #13 observability additions.

**IISS-971 — MESO Scheduled Reports Infrastructure**

4. SQS Queue Policy Forced Reapplication — DependsOn and Sid Bump
The SQS scheduled reports queue policy was not being applied during CloudFormation stack updates due to update caching behaviour. The issue was resolved by adding an explicit `DependsOn` reference from the policy to the queue resource, and bumping the `Sid` value in the policy statement to force CloudFormation to treat it as a new resource requiring application. This pattern is now documented as the standard approach for SQS policy reapplication issues.
