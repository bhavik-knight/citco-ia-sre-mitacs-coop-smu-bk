**IISS-1050 — SMB Retry Decorator: TRANSFER_FAILED Prevention (SD #15645338)**

- Scheduled Report Email — Status Colour Coding and Border Styling
The HTML email generated by the unified notification module lacked visual differentiation between report statuses. White cell borders were added throughout the status table to improve readability. Green highlighting was applied to `COMPLETE` and `SUCCESS` states, and red highlighting to `FAILED` states, making the operational outcome immediately visible without requiring text parsing.

- Green Condition Tightening — Preventing False Positive Status Highlights
The green highlight condition was using a truthy string match that inadvertently matched `IN-PROGRESS` and other intermediate states. The condition was tightened to an exact string comparison against `SUCCESS` and `COMPLETE` only, eliminating false positive green highlights on non-terminal states.

- IISS-1050 Final PR Merge — Feature Branch Completed
Pull request #14 was merged, completing the IISS-1050 feature branch. The merged code includes the retry decorator, unified email module, Pydantic request/response models, trace ID wiring, and all observability improvements accumulated across the development cycle.

- PROD Pipeline Trigger — IISS-1050 Deployed to Production

**IISS-971 — Migrate Scheduled Reports: APScheduler → EventBridge Scheduler → SQS**

- EventBridge Rules to Scheduler Migration — DST-Aware Cron Expressions
The MESO scheduled report triggers were migrated from EventBridge Rules (UTC-only) to EventBridge Scheduler, which supports timezone-aware cron expressions. Schedules were configured with `Australia/Sydney` and `America/New_York` timezone settings, ensuring correct trigger times regardless of daylight saving transitions. The Sep 23 KMS and IAM permission blockers were resolved prior to this migration.

- EDT Cron Adjustment and DEV Environment Isolation
Cron expressions were adjusted for the current Eastern Daylight Time offset (UTC-4). Scheduler rules in the DEV environment were disabled to prevent duplicate trigger processing during parallel DEV/PROD testing, isolating each environment's message flow.
