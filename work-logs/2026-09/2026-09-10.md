## Timecard

**ml-rpa-status-llm-agent — Bedrock Agent Instruction Architecture**

1. Instruction Extraction to instruction.md — Version-Controlled Agent Behaviour
The Bedrock agent instruction was previously embedded as a CFN parameter value, making it invisible to code review, untestable in isolation, and requiring a full stack deployment to update. The instruction was extracted to `agent/instruction.md`, a plain text file committed to the repository. The `buildspec.yml` was updated to apply the instruction file via the `update-agent` API call during deployment. This change makes agent behaviour as reviewable and auditable as application code.

2. Global Markdown Formatting Rules — Sonnet 5 Response Consistency
A set of global formatting rules was added to the instruction to govern Sonnet 5 response structure: prefer tables over bullet lists for structured data, use headers to separate multi-topic responses, and limit nesting to 3 levels. These rules address the observed pattern where Sonnet 5 would produce well-formatted responses in some query types but revert to unstructured output in others.

3. AgentInstruction CFN Parameter Removal — Decoupled Deployment Model
The `AgentInstruction` CloudFormation parameter was removed from the template, eliminating the 4000-character parameter length limit that constrained instruction complexity. The instruction is now applied exclusively through the `buildspec.yml` `update-agent` step, completely decoupling instruction content from infrastructure deployment. An instruction update no longer requires a CFN changeset.

4. ASCII Encoding Fix — CodeBuild Unicode Compatibility
The extracted `instruction.md` initially contained unicode characters (em-dashes, directional quotes) carried over from the original CFN parameter value. CodeBuild's default encoding configuration was mangling these characters during the file copy operation, corrupting the instruction text sent to Bedrock. All unicode characters were replaced with ASCII equivalents.
