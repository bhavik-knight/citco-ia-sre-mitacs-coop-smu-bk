## Problem Statement

The "meridian" trace group only captures Meridian traces OCCASIONALLY — not consistently.

When querying traces using the "meridian" group filter in the CloudWatch X-Ray console, 
trace ID 1-6a620a2a-431b91912f74e71c2a7a64b8 does NOT appear, even though it clearly 
involves multiple meridian-named services.

---

## Root Cause (Already Identified)

The segment document reveals that meridian_config_learning_agent.DEFAULT has a "parent_id" 
field ("parent_id": "c229befad5a6b171"), meaning the Meridian agents are NOT always the 
root/entry-point segment of the trace.

AWS X-Ray group filter expressions using service() are evaluated at ingestion time against 
the ROOT segment of the trace (the segment with no parent_id). 

When an upstream service (e.g., a CTI service or another orchestrator) initiates the trace 
and calls into the Meridian agents as downstream children, the root segment name does NOT 
contain "meridian" — so the filter service("*meridian*") does NOT match, and the trace is 
never indexed under the meridian group.

The Meridian agents only appear consistently in the group when they themselves are the 
root/entry-point of the trace (i.e., invoked directly, not via an upstream caller).

# Time wrapper - measure process_time in millisecond


def time_operation(func):
    """Decorator to measure execution time of a function in milliseconds."""
    from time import process_time_ns

    def wrapper(*args, **kwargs):
        start = process_time_ns()
        time_result = func(*args, **kwargs)
        end = process_time_ns()
        return time_result, (end - start) / 10**6  # milliseconds

    return wrapper
