The detailed process
 
constants.py loads credentials once at module import time (when the container starts). The credentials are stored in module-level variables (UCM_USER_NAME, UCM_USER_PASSWORD) for the lifetime of the container. So:
 
If the Secrets Manager call fails or returns empty at startup → credentials stay empty for the entire container lifecycle

Restarting ECS = new container = fresh import of constants.py = fresh call to Secrets Manager

If the secret is valid at that point, the new container picks up good credentials

This also explains why:

Option 1: Refresh credentials periodically (code change)
Modify constants.py to reload the UCM secret before each upload instead of caching at startup:
# Instead of module-level constants:def get_ucm_credentials():
    """Fetch fresh UCM credentials from Secrets Manager."""    ucm_login = json.loads(get_secret(os.environ['UCM_SECRET']))
    username = ucm_login.get('ucm_username', '')
    password = ucm_login.get('ucm_password', '')
    if not username or not password:
        raise RuntimeError(...)
    return username, password
Then in email_function.py / wherever upload is called:
user, passw = const.get_ucm_credentials()
upload_to_share(logger, destination, "Zips", zipname, user, passw, ...)
Pros: Self-healing — always gets fresh credentials, no restart needed
Cons: Adds a Secrets Manager API call per upload (~50ms latency), slight cost increase, more code changes needed across multiple files
Option 2: Fix the secret rotation (infrastructure change)
Work with the infra/security team to ensure the IA-BPO/UCM/PRD/credentials secret:
Never has an empty rotation window (old secret stays valid until new one is confirmed)
Has rotation notifications set up
Optionally: set up a CloudWatch alarm on the secret's RotationSucceeded / RotationFailed events
Pros: Zero code change, addresses root cause at the source
Cons: Requires cross-team coordination, doesn't protect against other failure modes (Secrets Manager timeout, network blip at startup)
My recommendation: both, but prioritize differently
Priority	What	Why
Immediate	Our hotfix (fail-fast + clear error)	Already done, deploy now
Short-term	Option 1 (refresh per upload)	Self-healing, no restart needed, protects against all credential failure modes
Long-term	Option 2 (fix rotation)	Root cause, but needs infra team involvement
 
Option 1 is the better permanent code fix because:
It doesn't depend on another team
It handles ALL credential failure scenarios (rotation, expiry, network blip at startup)
The container never gets stuck with stale credentials
Secrets Manager calls are cheap (~$0.05 per 10,000 calls)
For this process's volume (maybe a few hundred uploads per day), the latency/cost is negligible
